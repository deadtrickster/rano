encoding: a binary is not text, and it is read-only so it cannot be corrupted

**This was a correctness hole, not a cosmetic one.** Nothing in rano looked at whether a
file was text: a `.pyc` or a tarball went through the encoding ladder, fell to cp1252, and
became rows of mojibake — and then `^O` would happily write those rows back, *corrupting
the file*, because the character model cannot round-trip bytes it never decoded.

**The rule is git's**, taken rather than invented: a NUL byte in the first 8000 bytes
(`buffer_is_binary()` in git's `diff.c`; libgit2 adds a printable-ratio on top, and a NUL
alone has been enough for git for twenty years). `encoding::is_binary`, with the probe size
as `BINARY_PROBE`. No text rano decodes contains a NUL — UTF-8 no, cp1252 no (0xE9 is `é`,
not `\0`) — so the signal is decisive and cheap. A NUL *past* the probe is not evidence, and
that is tested both ways.

**It runs after the encoding decision, and that ordering was a test failure.** UTF-16 is
text whose bytes are *half NULs*, so a probe before the ladder stole every UTF-16 file from
the eager path that supports it. `utf16_is_declined_for_the_eager_path` and
`a_loading_utf16_file_falls_back_to_the_eager_path` caught it on the first run. A file that
reaches the probe is therefore one whose rows split on byte newlines, where a NUL means what
git says it means.

**Writing it as a view is the fix, not a warning.** `Buffer::binary` is set from the bytes
before any row exists; `BufferState::new` makes such a buffer `read_only`, the same rule a
tailed file follows (§20.6) — refused at the keystroke, where there is no correct save to
make. And the reader **stops after one chunk**: a 2 GB tarball costs one 64 KiB read and a
message rather than a whole file of rows. Nothing is put in the buffer either, because
64 KiB of mojibake is worse than saying so. A chosen mode (`M-x Mode`) still wins over the
default, because that is what choosing means.

`refresh_rows` and `parse_for_diagnostics` treat a binary as `None` under `Detected`, so it
is never highlighted: no grammar describes decoded noise.

Verified on `/bin/ls` in a terminal: title `VIEW`, text area empty but for the gutter, status
`[ Binary file — not shown (read only) ]`, and typing it says `[ Read-only buffer — typing
refused ]`.

Tests: 4 — the rule (a NUL is a binary; text of every kind is not; only the first probe
counts, both directions) and the behaviour (nothing read into rows, read-only, typing
refused, no language). 1077 lib tests pass.
