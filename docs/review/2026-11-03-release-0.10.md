# Release 0.10.0 review panel

Adversarial review of rano at `97adbc5` (after the deslop pass), before cutting 0.10.0.
Three positions, two rounds, models rotated between rounds. Reports are kept verbatim.

| Position | Round 1 | Round 2 |
|---|---|---|
| 1. Not releasable: it can lose a file or crash in ordinary use | deepseek-flash | Opus |
| 2. Releasable: tests and guards bound the risk | Opus | Fable |
| 3. Against both: the design makes the next defects | Fable | deepseek-flash |

## Round 1

### Position 1 (deepseek-flash)

## Thesis

rano's text path is guarded; its **I/O boundary is not**. Five places where it touches the OS — save, `^T`, `M-|`, tail-open, undo retention — have no atomicity, no deadline, or no byte budget. In each, the failure mode is a destroyed file or a dead editor, not a wrong pixel. That is a release blocker for 0.10.0, and it is not one a test can find by asserting a return value.

## Evidence

**1. Save is not atomic.** `src/editor.rs:2667` — `fs::write(&path, encoded)`: truncate-in-place, no temp, no `rename`, no `sync_all`. ENOSPC or a kill mid-write leaves a truncated file while the status line says `Error:` and the buffer stays `modified` (`editor.rs:2692-2697`) — the user reads that as "nothing happened", quits declining to save, and the original is gone. `src/update.rs:271-289` does tmp+rename for the *binary*; the codebase knows the pattern and did not use it for user data. Worse, the save thread builds the document three times first — `file_bytes()` (`buffer.rs:288`), `format_for_save`'s `buf.text()` (`editor.rs:2606`), `run_save_hook`'s again (`editor.rs:3207`) — so on a large buffer the OOM abort lands *inside* the non-atomic write. `DiskStamp` is mtime+len only (`buffer.rs:9-24`), so an equal-length change in the same tick is silently overwritten.

**2. `^T` can freeze the editor forever.** `src/exec.rs:58-60`: `try_wait`, then `rx.recv()`, on the poll (UI) thread, with the comment asserting recv "cannot block: the child's exit closes the pipes". False whenever the child leaves a grandchild holding stdout — `^T make -j`, `ssh h cmd`, `sh -c 'daemon &'`. `exec_poll` then blocks with no key handling and no way out. Same file: `read_to_end` into one `Vec` (`exec.rs:45-49`), no cap: `^T yes` OOMs.

**3. `M-|` blocks with no timeout.** `src/exec_ctrl.rs:129` — `child.wait_with_output()` synchronously, no deadline, no kill, no process group. Contrast `run_filter` (`exec_ctrl.rs:171-230`), which has one for the save path. Killing rano orphans the `sh`.

**4. Undo is bounded in steps, unbounded in bytes.** `editor.rs:936` `UNDO_LIMIT = 500`, each step holding full `before`/`after` row copies (`editor.rs:1028,1046`). Whole-file `M-|`, gofmt-on-save and `on_save` transforms each record one: 500 whole-document copies retained.

**5. Tail-open of a newline-free large file reads it all.** `loader.rs:234-238,278`: window 64 KiB, `*= 4` per round, `vec![0u8; size - win_start]`, synchronously (`load_ctrl.rs:129`). A 5 GB minified file allocates 5 GB before the first frame.

## Proposed changes

1. `atomic_write`: temp in the same dir, write, `sync_all`, copy the old file's mode, `rename`, fsync the parent; remove the temp and leave the original on any error. Stream the encode row-by-row instead of `file_bytes()`. Test: force a write error and assert the original bytes survive.
2. `try_finish`: `rx.try_recv()` and report "child exited; a process it started still holds the pipe". Cap each stream at e.g. 16 MiB.
3. Filter becomes a job like exec — polled, deadline'd, Esc-cancels, buffer untouched on timeout. Put children in their own process group; SIGKILL the group from a `Drop`.
4. Evict undo until retained rows < 64 MiB, not just under 500 steps.
5. Cap the tail window at 8 MiB, then start at the next newline after it; run `tail_offset` on the reader thread.
6. Cap LSP `Content-Length` before `vec![0u8; len]` (`lsp.rs:266`).

## Concessions

POS2 is right about most of the code I tested: plugin sandboxing is genuinely good (fuel, store limiter, `MAX_HOOK_BYTES`, refusal rather than clipping); every width/cursor calculation I traced is saturating and guarded (`width.rs:158`, `ui.rs:301,319,397` with `gutter_width ≥ 3`); CRLF and cp1252/UTF-16 round-trip and *error* rather than substitute (`buffer.rs:288`); the external-change prompt with a `d` diff (`editor.rs:2483-2546`) beats nano. **I found no reachable panic** in the render path — I will not overclaim one. That is the point: the defensible code is the text code, and none of it guards the moments rano writes to disk or waits on a child.

### Position 2 (Opus)

POS2 (releasable), round 1.

**Thesis.** 0.10.0 can ship once three small fixes land, each under 30 lines. The release path is guarded well enough that a broken artifact is unlikely, and most crash and data-loss paths I traced already have a guard. One truncation path I found is unguarded and not in TODO.md. It is a real blocker, and the fix is small.

**Evidence: guards that hold (traced end to end)**
- Release: the `names` job fails a tag that disagrees with Cargo.toml (`release.yml:43-58`). It checks the runner arch (`:87-96`), runs the binary before packaging, including the cross build (`:111-118`), and checks that every asset extracts to an executable `rano` before publishing (`:151-164`). CI runs fmt, clippy `-D warnings`, test, release build, export smoke tests, install.sh and dist-name checks, on Linux and macOS (`ci.yml`).
- Autoupdate: only HTTPS, curl `-q`, a strict MAJOR.MINOR.PATCH compare, and `0.9 -> 0.10` is pinned numerically (`tests/update_check.rs:77`). The tar extractor is bounds-checked (`update.rs:225`). The binary is swapped by temp file plus rename (`update.rs:271-289`).
- Save:
  - external-change prompt with y/n/d (`editor.rs:2456-2469`)
  - read-only refusal (`editor.rs:1075`)
  - binary files and tails are read-only (`load_ctrl.rs:138`, `:238`)
  - a jump into a buffer that is still loading reads the file whole first, and only when the buffer is unmodified (`load_ctrl.rs:399-407`)
  - a panic hook restores the terminal (`Cargo.toml:65`)
  - a terminal that is too short gets a message instead of a draw (`ui.rs:301`)
- Tests: 1301 `#[test]`, 34 ignored, 215 in `ed_tests`. Save coverage includes CRLF, external change, read-only, and a trapping plugin (`ed_tests.rs:182`, `:226`, `:1197`, `:4205`).

**What the tests do not pin.**
- No test saves after a partial load.
- Nothing spawns the binary (TODO.md:224).
- `stale_range_sweep` is `#[ignore]`d, and CI runs without `--ignored`, so the guard against the markdown panic never runs in CI.
- release.yml never runs `cargo test` and does not require CI to be green on the tagged commit.

**Blockers, with the smallest fix for each**
1. **Truncation after an edit during a load (new finding).** An edit while a file is loading cancels the load, keeps only the rows that arrived and sets `modified` (`editor.rs:881-887`). The test `load_ctrl.rs:533` pins this as intended. ^O then reaches `write_file`, and `changed_on_disk` is false because the file itself has not changed, so the partial buffer is written over the whole file. ^C at quit (`editor.rs:3394`) and "Read failed" (`load_ctrl.rs:340`) leave a partial buffer the same way. This is ordinary use on any file large enough to take a few frames to load, and multi-GB files are advertised.
   - Fix: add `BufferState::partial: bool`. Set it wherever a load that is not `caught_up()` is cancelled or fails.
   - In `save_to`, refuse a write to the buffer's own path while `partial` is set: "only N lines were read - save under another name".
   - Extend `load_ctrl.rs:533`: save, then assert the file on disk is unchanged.
2. **Completion popup panics in a narrow pane.**
   - `ui.rs:473`: `clamp(10, width.min(60))` panics when the pane is under 10 columns.
   - `ui.rs:510`: `w - 2 - label - tag` underflows once the pane is narrower than the label plus about 8 columns. The release profile does not check overflow, so `" ".repeat(huge)` aborts on capacity overflow.
   - Narrow panes are normal in letibot, so this is a blocker for an embedding release. It is already listed at TODO.md:12.
   - Fix: `clamp(10.min(width), width.min(60))` and `saturating_sub` for the padding. Add a test with a 40-character label at widths 8 and 20.
3. **Version.** Cargo.toml says `0.9.1` (`Cargo.toml:3`). The guard rejects a `v0.10.0` tag, so this is a step, not a risk. Bump Cargo.toml and Cargo.lock in the release commit.

**Should-fix that does not block**
- Atomic save (TODO.md:15, `editor.rs:2667` `fs::write`). nano truncates in place too, and only a full disk or a crash mid-write exposes it. `replace_running` already has the temp-plus-rename shape to reuse, plus copying the file mode. About 20 lines.
- Add a `cargo test` step to the release `build` job, so a tag on a red commit cannot publish.
- Run `stale_range_sweep` in CI with `-- --ignored stale_range` (it is a single test).

**Embedding.** The library surface hangs together for a host:
- a non-blocking `Editor::tick` and `next_wakeup` (`host.rs:20`)
- `push_keymap`, whose unknown command names come back as `KeyOutcome::Host`
- `render`, which has no dependency on host crates
- `pub` diff, sidediff, patch, conflict and send modules

Blocker 2 is the only embedding hazard I found.

**Concessions, for POS1 and POS3**
- Blocker 1 is real data loss, and a test pins the behavior as intended, which weakens "the tests bound the risk".
- The library surface is wider than needed. `logsearch` and `logtail` are `pub` with no caller (`lib.rs:76-81`), and `update` is public.
- Two of the four known crash and data-loss TODOs (TODO.md:12, :15) were open at the release cut.
- The orphaned `^T` child (TODO.md:18) and the `M-|` UI block (TODO.md:20) are real, but they leak a process or hang the UI. They do not lose data, so they are not blockers.

### Position 3 (Fable)

## Thesis

rano's next defects will come from state shape, not from missing tests. `Editor` is a 66-field bag of independent `Option`s and `bool` flags with the "which mode am I in" decision re-derived, in different orders, in three files. Save, wrap and prompt handling each interleave 4-6 concerns in one function. Everything is tested after the fact; nothing makes the invariants structural.

## Evidence

Modal state is implicit. `src/editor.rs:148-217`: `prompt`, `palette`, `info`, `picker`, `diff_view`, `picture_view`, `completion`, `replace` are eight independent `Option`s, all `pub` (a host can set two at once). Key priority: `src/keys.rs:113-175` (completion > host chord > prompt), then `src/commands.rs` `editor_keymaps` (palette > info > diff > picker > dir). Draw priority: `src/ui.rs:462,529,552,573,688,691,723,738` in a different order, with line 691 hand-guarding `info.is_none() && picker.is_none() && diff_view.is_none()` for the prompt - a third encoding of the same rule. `dispatch_key` decides "typing inserts text" by `m.name == "global"` string compare (`src/commands.rs` Unbound arm). A new overlay must be threaded through all three sites; nothing fails if one is missed.

Save is six concerns in one function, mutating before writing. `src/editor.rs:2635-2697` `write_file`: mkdir prompt, `format_for_save`, `run_save_hook` (plugin rewrites the buffer), encode, `fs::write`, LSP flush, then the `quit_after_save`/`close_after_save` boolean continuation. `fs::write` truncates in place - no temp+rename, no fsync - while the project's own self-update does it right (`src/update.rs:276-285`). gofmt and the plugin hook have already replaced the buffer when the write fails. POS1 will cite the data-loss path; I say it exists because the function has no seam where "bytes to write" and "state after success" are separable.

Wrap cache is six fields with invariants checked by length equality. `src/bufstate.rs:79` plus `wrap_key/prefix/rows/lines/extend_from`; `ensure_wrap_prefix` (`src/editor.rs`) has three paths chosen by `len() == n + 1` comparisons. Any edit that cannot name a row (`edit_invalidate()` from `newline`, `backspace`, `undo`, `redo`, `paste`, `cut` - 16 callers in editor.rs) forces the full rebuild: `row_wrap_of_line` over every row, on the next key, with `wrap: true` default (`src/config.rs:116`) and no large-file opt-out (`grep 'wrap = '` finds only the toggle). Enter in a million-row buffer rescans a million rows.

Prompt kinds dispatch in two shapes. `src/prompt.rs:113-200` handles six `Confirm*` kinds by matching `KeyCode::Char` y/n per arm; `:203-250` handles twelve text kinds on Enter with `_ => {}`. 18 variants, two match ladders, a `_` catch-all in each - a new kind that lands in the wrong ladder silently does nothing.

Plugin: `read_dir` is unscoped (`src/plugin.rs:308-325`) while `read_file` and `convert_page` are scoped to the one file. A plugin granted `read-dir` lists `~/.ssh`. Also `let _ = linker.func_wrap(...)` x4 - a failed import registration becomes an opaque instantiation error.

Error style: 176 `let _ =` across src; `src/lsp.rs:596,602` ignore writes to a server that may be dead, and no `try_wait` anywhere detects exit, so a crashed server degrades to silence.

## Proposed changes

1. `enum Overlay { None, Prompt(Prompt), Palette(..), Info(..), Picker(..), Diff(..), Completion(..) }` on `Editor`, one `fn overlay_keymaps()` and one `fn draw_overlay()` switching on it. Deletes `ui.rs:691`. Make the field `pub(crate)`.
2. Split `write_file` into `fn save_bytes(&self) -> Result<Vec<u8>>` (format/hook on a clone, not the buffer), `fn write_atomic(path, bytes)` (temp in same dir, `sync_all`, `rename`, as update.rs does), `fn after_save(path)`. Replace `quit_after_save`/`close_after_save` with `enum AfterSave`.
3. `struct WrapTable` owning the six fields with `fn edited_row`, `fn rows_changed(from)`, `fn appended(from)`; callers that split or join lines report the row instead of `None`, so Enter is O(rows after cursor), not O(n).
4. One `fn prompt_submit(kind, text)` and one `fn prompt_answer(kind, yes: bool)` table; delete both `_ => {}`.
5. Scope `read_dir` to the opened file's directory tree, like `read_file`.

## Concessions

Binary/library split is clean: `main.rs` uses only `rano::` (`:7-13`), `host.rs` tick is the one loop. `every_bound_command_exists_and_every_name_is_unique` (`src/commands.rs:1281`) guards keymap/command drift. Fuel, memory limiter and 16 MiB payload cap are real. LSP `pending` does not leak (`wait` removes). `Style` is `Copy`; per-cell styling is fine. 1301 tests. POS2 is right that it is releasable; it is not right that it is safe to change.

## Synthesis and decisions

All three positions agree on four release blockers. Each lands with a test.

1. A partial buffer must not be saved over its own file. A save during a load writes only the
   rows that arrived (position 3, round 2: no edit needed), and so does a save after an edit
   cancelled the load, after ^C cancelled it, or after a read failed (position 2). Fix: track a
   partial buffer (a load in flight, pending, cancelled or failed) and refuse to write it to its
   own path. Saving under another name stays possible.
2. `^T` can freeze the UI: `try_finish` blocks on `rx.recv()` after the child exits while a
   grandchild holds the pipe (`src/exec.rs:59`). Fix: `try_recv`, with a short grace, then finish
   with what arrived.
3. The completion popup panics in a narrow pane (`src/ui.rs:473` clamp, `:510` underflow). Fix:
   clamp within the width, `saturating_sub` for the padding.
4. Version 0.10.0 in `Cargo.toml` and `Cargo.lock` (the release job checks the tag against it).

Disputed, decided:

5. Atomic save. Positions 1 and 3 call it a blocker, position 2 a should-fix. Decision: fix it
   now. It is small (temp file in the same directory, `sync_all`, keep the mode, `rename`), the
   pattern exists in `src/update.rs`, and the failure is a destroyed file.
6. `M-|` blocking the UI with no deadline (`src/exec_ctrl.rs:129`). Position 1 wants it now,
   position 2 calls it expected blocking. Decision: follow-up. It hangs the UI but loses no data,
   and moving the filter onto the polled job path is a larger change than this release should
   carry.
7. One overlay state (position 3). Decision: follow-up. It is the right shape but a cross-cutting
   refactor, not a release fix.
8. Position 2 round 2 dropped the `stale_range_sweep` claim as naming no test. The gate run lists
   `tests/stale_range_sweep.rs` with one ignored test, so the round-1 claim stands: CI does not
   run it. Follow-up.

Follow-ups, recorded in TODO.md with a link here: `M-|` as a polled job with a deadline; one
overlay state for keys, dispatch, drawing and the cursor; save split into bytes-to-write and
after-save state, encoded from a clone; a wrap table that updates per row (Enter is a full
rebuild); one table each for prompt submit and answer; scope plugin `read_dir`; an undo byte
